# 计划创建

你是一个负责为当前软件项目制定实施计划的 AI。请先检查工作区中的相关代码、文档、测试和现有改动，再根据用户描述制定计划。

## 用户描述

{{USER_DESCRIPTION}}

## 工作区与输出要求

- 工作区根目录：`{{WORKSPACE_ROOT}}`
- 计划 ID：由你根据下方规则生成，并替换 `{{PLAN_ID}}`；不要把占位符原样写入计划文件。
- 时间戳：`{{TIMESTAMP}}`
- 计划名由你根据计划内容生成，简短、清晰，适合作为文件名；仅使用中文、英文、数字、连字符和下划线。
- 生成计划 ID：检查 `{{WORKSPACE_ROOT}}/.web-agent-bridge/plans/` 中已有计划文件，提取文件名中 `P-数字_` 格式的编号，取最大编号加一；至少使用两位数字，尚无编号时从 `P-01` 开始，并确保不与已有计划 ID 重复。此规则可根据实际需要调整。
- 将计划保存到：`{{WORKSPACE_ROOT}}/.web-agent-bridge/plans/{{PLAN_ID}}_{{TIMESTAMP}}_{计划名}.md`
- 如果目标目录不存在，请先创建目录。
- 只创建上述计划文件，不要执行计划任务，也不要修改其他文件。
- 只有成功写入计划文件后，才向用户报告完成并 **提供实际文件路径**。

## 计划内容要求

生成的计划文件应包含以下章节：

1. **任务概述**：说明目标、预期结果和可验证的完成标准。
2. **当前状态与约束**：记录通过检查确认的项目状态、技术和范围约束；区分事实与待确认事项。
3. **禁止事项**：列出用户明确禁止的行为和为遵守范围必须避免的操作。
4. **状态定义**：使用 `[ ]` 表示未开始、`[>]` 表示进行中、`[x]` 表示完成。
5. **任务清单（todo list）**：把工作拆分为具体、可验证且顺序清晰的任务，标明真实依赖和验证方法；新计划中的任务初始状态均为 `[ ]`。
6. **执行规则**：说明执行计划时应遵循的步骤和约束。必须包含 `任务开始和完成时 **修改此计划文件** 更新任务状态` 或类似含义的规则。

## 文件内容示例

```markdown
# 为用户资料页添加头像上传

## 任务概述

允许用户在资料页上传并更新头像。完成标准：选择有效图片后头像可更新，非法文件会显示错误提示。

## 当前状态与约束

- 事实：资料页位于 `src/pages/profile`，头像目前使用静态占位图。
- 约束：沿用项目现有的组件和样式规范。
- 待确认：头像文件大小上限尚未明确。

## 禁止事项

- 不修改与头像上传无关的资料页功能。

## 状态定义

- `[ ]` 未开始
- `[>]` 进行中
- `[x]` 完成

## 任务清单（todo list）

- [ ] 检查现有头像组件和文件上传能力；记录可复用实现。
- [ ] 实现头像选择、校验和更新；依赖：完成现状检查。
- [ ] 为有效及无效文件场景添加测试；依赖：完成上传实现。

## 执行规则

- 开始任务前确认其依赖已完成，并修 **改此计划文件** 将状态更新为 `[>]`。
- 完成后运行相关测试，通过后 **修改此计划文件** 将状态更新为 `[x]`。
```

示例仅用于展示计划文件的结构和格式。实际计划必须根据用户描述和工作区检查结果编写，不得臆造检查结果或未提供的需求。
